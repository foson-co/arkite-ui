# Recipes

Each recipe is a whole page assembled from the library — not a prop showcase.
They exist because the hard part is rarely picking a component; it is knowing
which components go together, who owns which piece of state, and which pairings
break. Read the one closest to the page you are building, then adapt.

| Recipe | What it shows |
|---|---|
| [CRUD List Page](?path=/docs/recipes-crud-list-page--docs) | Search + filters over a sortable, selectable, paginated table; bulk actions; a guarded destructive path |
| [Server-Side Table](?path=/docs/recipes-server-side-table--docs) | The same list when the server does the filtering, sorting, and slicing (`totalRows` + `useServerTable`) |
| [Dashboard](?path=/docs/recipes-dashboard--docs) | KPI tiles, sparklines, and a compact activity table in one grid |
| [Detail + Drawer Edit](?path=/docs/recipes-detail-drawer-edit--docs) | A read view with an edit drawer, plus a confirmed destructive action |

| [Tenant Admin Shell](?path=/docs/recipes-tenant-admin-shell--docs) | The app frame: `AdminLayout`, tenant switching, sub-navigation |

## Machine-readable index

Every recipe on this page is also an entry in **`registry.json`**, which ships
inside the npm package. Each entry carries the fields a *selector* needs — not
just what the recipe is, but `when` to reach for it and `notWhen` it is the
wrong shape — plus the exports it composes and the path to its source.

That index feeds `llms.txt`, so an AI agent asked for "a list page with
server-side pagination" gets a tested composition to copy instead of inventing
the wiring from prop signatures. `src/registry.test.ts` fails CI if a recipe's
`uses` list drifts from what the demo actually imports, or if a demo exists
with no entry — a stale index would teach the wrong pattern at scale, which is
worse than having none.

## Before you copy one

Recipes show composition, not every rule. The pairings that fail *silently* —
wide tables without `minWidth`, `stickyHeader` without a height limit, a
`DataTable` nested in a `Card` — are collected in **Composition rules** in
`DESIGN.md`, and four of them now warn at dev time.

# Theme System

Arkite UI uses **HSL CSS variables** for theming. All colors are defined as CSS custom properties,
making it easy to switch themes at runtime.

## Dark Mode

Toggle dark mode by adding/removing the `dark` class on `<html>`:

```ts
// Toggle
document.documentElement.classList.toggle('dark')

// Set explicitly
document.documentElement.classList.add('dark')    // dark
document.documentElement.classList.remove('dark')  // light
```

## Preset Themes

4 built-in presets: `default`, `neutral`, `ocean`, `forest`.

```tsx
import { themePresets, applyTheme, applyDarkTheme } from '@arkite-ui/core'

// Apply a preset
applyTheme(themePresets.ocean)

// Apply dark variant
applyDarkTheme(themePresets.ocean)
```

## Custom Themes

Create a theme from 1-2 hex colors:

```tsx
import { createTheme, applyTheme } from '@arkite-ui/core'

const myTheme = createTheme({
  name: 'brand',
  primary: '#FF6B00',
  accent: '#00B4D8',
  radius: '0.75rem',
})

applyTheme(myTheme)
```

Foregrounds are computed from the actual WCAG contrast ratio — black or white, whichever reads better on your brand color, in both light and dark mode. Every generated pair is guaranteed to meet AA (4.5:1), so any hex value is safe. If you override CSS variables by hand instead, validate the palette with the **Foundation / Design Tokens → Contrast Audit** page.

## Theme File (`arkite.theme.json`)

A brand copied as CSS variables into nine repos drifts, and nothing can tell you *how much*. Commit the four inputs instead and generate the rest:

```json
{ "name": "acme", "primary": "#6a4dff", "accent": "#00b4d8", "radius": "0.5rem" }
```

```bash
npx arkite-ui theme apply                      # → src/styles/arkite-theme.css
npx arkite-ui theme apply --print               # stdout, for a build pipeline
npx arkite-ui theme apply brand.json --out src/brand.css
npx arkite-ui theme apply --selector '[data-tenant="acme"]'   # scoped, per tenant
```

Import the generated file **after** the library stylesheet. The file is marked generated — edit the JSON and re-run instead, so the artifact stays the source of truth.

The **Foundation / Theme Playground** page produces this JSON interactively: pick colors, watch the components repaint, copy the file out.

Same generation is available in-process — server-safe, no components loaded:

```ts
import { parseThemeFile, themeFileToCSS } from '@arkite-ui/core/theme'

const css = themeFileToCSS(parseThemeFile(JSON.parse(json)))
```

`parseThemeFile` is strict on purpose: `createTheme` turns a malformed hex into `NaN NaN% NaN%` and the failure only shows up as an unstyled app, so a bad value is rejected where it is written. Unknown keys are errors too — a typo'd `primaryColor` would otherwise silently ship the default brand.

## SSR / Style Tag

Generate a CSS string for server-side rendering:

```tsx
import { themeToCSS, themePresets } from '@arkite-ui/core'

const css = themeToCSS(themePresets.default)
// Returns: :root { --primary: 250 100% 65%; ... } .dark { ... }
```

## Available Tokens

| Token | Light Default | Usage |
|-------|--------------|-------|
| `--primary` | `250 100% 65%` | Brand color, CTA buttons |
| `--secondary` | `220 14% 96%` | Secondary buttons, backgrounds |
| `--accent` | `168 80% 45%` | Accent highlights |
| `--destructive` | `0 72% 51%` | Delete, error states |
| `--success` | `145 65% 42%` | Success states |
| `--warning` | `38 92% 50%` | Warning states |
| `--info` | `217 91% 55%` | Informational states |
| `--muted` | `220 14% 96%` | Muted text, subtle backgrounds |
| `--background` | `0 0% 100%` | Page background |
| `--foreground` | `220 15% 20%` | Main text color |
| `--border` | `220 13% 91%` | Border color |
| `--radius` | `0.5rem` | Border radius base |

Each status color (`success`, `warning`, `destructive`, `info`) also has a **soft layer**
for pale, tinted surfaces (Alert, Toast, soft Badge):

| Token | Light Default (success) | Usage |
|-------|------------------------|-------|
| `--{status}-soft` | `138 76% 97%` | Pale status background |
| `--{status}-soft-foreground` | `143 64% 24%` | Readable text on the soft background |
| `--{status}-border` | `141 79% 85%` | Pale status border |

Use them via utilities like `bg-success-soft`, `text-info-soft-foreground`, `border-warning-border`.

## Elevation Shadows

Consistent depth system for layered UI:

| Token | Use Case |
|-------|----------|
| `shadow-xs` | Input, Badge |
| `shadow-sm` | Card, Dropdown |
| `shadow-md` | Popover, Toast |
| `shadow-lg` | Modal, Drawer |
| `shadow-xl` | Command Palette |
| `shadow-2xl` | Full-screen overlay |
| `shadow-sticky-left` | Table sticky action column separator |
| `shadow-sticky-header` | Table sticky header bottom hairline |

## Overriding Tokens

Override any token in your project's CSS:

```css
:root {
  --primary: 210 100% 50%;
  --radius: 0.75rem;
}
```
